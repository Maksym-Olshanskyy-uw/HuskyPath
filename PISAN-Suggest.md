## Project Summary

HuskyPath is an AI-assisted course scheduler for UW students. Users describe their preferences in natural language ("no classes before 10am, light Friday, avoid back-to-back lectures") and the system returns ranked, conflict-free schedules from UW Time Schedule data, each annotated with a plain-language explanation. The stack is a React 19 + Vite frontend (`client/`) and a Node.js + Express 5 backend (`server/`), with Google Gemini (`gemini-2.5-flash`) handling the NLP constraint extraction. Contributors per `git shortlog`: Ryan Locquiao (9 commits, mostly frontend and merges), Kieran Moynihan (5 commits, scraper / scheduler / scorer / plan endpoint), Maksym Olshanskyy (2 commits, NLP parser).

## Suggested Improvements & New Features

### Code Quality & Technical

- **Fix the deployment.** `https://huskypath.vercel.app` returns 404 `DEPLOYMENT_NOT_FOUND`. Re-link the GitHub repo to a Vercel project, or redeploy. Without this, the entire project is invisible to a grader who follows the README link. Add a `vercel.json` and document the deploy step.
- **Wire the frontend to the real backend.** `client/src/App.jsx:26` calls `/api/parse` (which 404s) and silently falls back to `MOCK_SCHEDULES`. Change the URL to `POST /api/plan`, send `{ text, courseCodes, topN }` per the spec in `server/routes/plan.js:26-46`, and remove the mock fallback (or gate it behind `import.meta.env.DEV` so production failures surface as errors).
- **Reconcile the day-code shapes.** Server emits `['M','T','W','Th','F']`; `client/src/components/WeeklyCalendar.jsx:3` expects `['Mon','Tue','Wed','Thu','Fri']`. Add a tiny adapter (or change one side) so real backend data renders.
- **Reconcile constraint schemas.** The parser produces `avoid_days` / `avoid_consecutive`; the scorer in `server/services/scorer.js:156-220` checks `light_days`, `preferred_times`, `avoid_consecutive`. Either extend the Gemini prompt in `server/services/constraintParser.js:124-167` to emit the richer schema, or document that `light_days` and `preferred_times` are caller-supplied only.
- **Fix the README's AI claim.** `README.md:30` says "Anthropic Claude API"; the code uses Gemini. Update the README, or actually swap in `@anthropic-ai/sdk` — the choice should be deliberate and documented (cost, JSON-mode reliability, etc.).
- **Add CI.** A 10-line `.github/workflows/test.yml` running `cd server && npm ci && npm test` would catch regressions on every PR and demonstrates engineering hygiene to the grader.
- **Remove or use the `pg` dependency.** It's listed in `server/package.json` and the README's "Backend" row, but never imported. Either implement the planned cache table or drop the dep until you do.
- **Tighten the scraper regex.** `server/services/uwScraper.js:47` is one long pattern that has not been validated against a live page (per your own roadmap). Capture sample HTML fixtures into `server/test/fixtures/` and write a test that parses them — this is the highest-leverage test you can add.

### UI / UX Improvements

- **Surface constraint extraction to the user.** After the AI parses the input, show the structured constraints (e.g., a chip row reading "Before 10am · No Friday · No back-to-back") so users can see and confirm what the AI understood before scheduling runs. This makes the AI's role visible and builds trust.
- **Show why a schedule scored as it did.** The backend already returns `breakdown` (`scorer.js:262-273`) with four numbers; render them as a small radar chart or four mini-bars next to each schedule card. Right now only the one-sentence `explanation` is shown.
- **Add empty/error states.** `App.jsx:44` swallows all fetch errors into the mock fallback. Show a real error UI ("Couldn't reach the scheduler — retry?") so failures are debuggable in production.
- **Accessibility pass.** The theme toggle uses `☀` / `☾` glyphs (`App.jsx:74`); confirm they read sensibly to screen readers given the `aria-label`. The calendar's `wc-event` blocks (`WeeklyCalendar.jsx:110-134`) need a focusable affordance for keyboard users.
- **Loading state should mention the AI step explicitly** ("Asking Gemini to parse your preferences…") so the AI integration is felt by the user, not just present in the architecture diagram.

### New Features

- **Degree-requirement awareness.** Let the user pick a major (CSE, INFO, MATH) and have the planner suggest the next required courses from a small curated dataset. This is the feature that would move HuskyPath from "nice utility" to "indispensable" for UW students.
- **RateMyProfessors / grade-distribution integration.** Your README and `scorer.js:121-149` already flag this as a TODO. Even a stale CSV of UW median GPAs by course/instructor would let the difficulty-curve dimension stop being a placeholder.
- **"Lock this section, regenerate the rest" interaction.** Once results are shown, let a user pin one section and re-rank around it. The backtracking scheduler in `server/services/scheduler.js:121-175` already supports this — just pre-populate `chosen` before the recursion.
- **Shareable schedule links.** Encode the chosen `sections[]` into a URL hash so students can DM a friend "what do you think of this quarter?" — a real UW behavior.
- **Conflict explanation.** When `generateCandidates()` returns `[]`, run a quick analysis ("CSE 311 lecture A and MATH 307 lecture B both meet MWF 10:30") and tell the user *why*, instead of just showing zero results.

### AI Integration Enhancements

- **Use the LLM for the explanation, not just the parser.** Right now `scorer.js:227-255` builds the per-schedule explanation from a fixed phrase table. Sending the breakdown + top-3 conflicts back to Gemini for a one-paragraph natural summary would make the AI integration end-to-end and noticeably more useful.
- **Few-shot the harder cases.** The current prompt (`constraintParser.js:124-167`) handles three simple examples. Add adversarial ones: "I work Tuesday mornings", "I need at least one class with Professor Loveless", "Keep my commute days to two." This both improves quality and demonstrates real prompt engineering.
- **Add a confidence / clarification turn.** If Gemini extracts a constraint with low confidence (or the JSON has nulls), have the UI ask one follow-up question ("Did you mean 'no classes before 10am every day' or just on Mondays?"). This is the kind of agentic loop that distinguishes "meaningful AI" from "API call."
- **Cache parsed constraints.** Hash the input text and cache the Gemini response in-memory (or Postgres, since you have the dep). UW students often re-run with slight wording changes; you can skip the API call when the text is identical and meaningfully reduce cost.
- **Consider a structured-output mode.** Gemini supports `responseSchema` natively now; using it would eliminate the `extractJson()` / `JSON.parse()` defense in `constraintParser.js:29-37` and make the parser more reliable.
